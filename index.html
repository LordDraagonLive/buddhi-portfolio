How I Think

UI/UX is not decoration. It is how complexity becomes usable.

I approach interfaces from the system outward: what the user is trying to decide, what the data needs to prove, and where the product can remove friction before it becomes support work.

01

Map the real workflow

Start with user intent, edge cases, roles, and operational pressure before choosing screens or components.

02

Design for confidence

Make states, permissions, errors, audits, and exports obvious so people can trust what they are doing.

03

Keep delivery maintainable

Shape API contracts, data models, and UI flows together so products stay coherent as features grow.
